# Проверка готовности MVP

Статус сформирован по текущему коду и автоматическим тестам.

| Область | Статус | Проверяемое поведение |
|---|---|---|
| Запуск и профиль | Готово | `/start`, анкета, расчет калорий и КБЖУ, принятие или корректировка каждой нормы, изменение профиля |
| Каталог | Готово | 159 продуктов и блюд USDA, поиск, страницы, личные продукты и изоляция доступа |
| Дневник питания | Готово | прием пищи предлагается по местному времени с переключением, ввод нескольких продуктов с подтверждением итоговых КБЖУ, снимки порций, изменение и удаление записей |
| Сегодня | Готово | калории, КБЖУ, вода, разбивка по приемам и пороговые уведомления |
| Вода и вес | Готово | быстрый и ручной ввод, история, исправление, удаление и прогресс веса |
| История, повтор и шаблоны | Готово | выбор даты, страницы, повтор продукта или приема, сохранение и повтор до 30 личных шаблонов с проверкой КБЖУ, недавние порции и избранные |
| Напоминания | Готово | еда, вода, утренний отчет, тихие часы, часовой пояс, snooze/skip, дедупликация и повторы ошибок |
| Справка и ошибки | Готово | `/help`, меню команд Telegram, безопасный ответ при неожиданной ошибке |
| Развертывание | Готово | Docker Compose, постоянный том, автоматические миграции и seed, healthcheck, graceful shutdown |
| Контроль качества | Готово | Ruff, тесты сервисов/репозиториев, чистая цепочка Alembic и жизненный цикл scheduler в CI |

Перед первым публичным запуском остается ручная приемка в тестовом Telegram-боте: пройти анкету, добавить и исправить еду/воду/вес, проверить часовой пояс и дождаться каждого типа напоминания. Автотесты не проверяют доступность Telegram API и внешний вид сообщений в конкретном клиенте.

Текущие эксплуатационные границы: один процесс с SQLite; бот работает в личных чатах; распознавание фото и штрихкодов, платежи, web-панель и медицинские рекомендации не входят в MVP.
